# 주문형 제안서 (고객 카톡방용 링크)

> **2026-10-30부터 새 주문서는 ERP에서 만든다.** ERP(app.open-garden.co.kr) '주문' 화면 → 품목 고르기 →
> [고객 링크 만들기] → `https://open-garden.co.kr/o/<ID>` 가 바로 생긴다(배포 불필요).
> 원본은 에어테이블 `[영업] 주문 링크`, 페이지는 `api/order-page.js`가 그린다. 마감은 그 표에서 상태를 '마감'으로.
> 아래 `/p/` 방식은 사진·특징을 손으로 꾸미는 특별 제안서용으로 남겨둔다. 두 방식 모두 `lib/order-page.js`로 그린다.
> `/o/` 품목JSON에는 `img`(이 사이트의 `/p/<ID>/img/<키>.jpg`만)·`feat`·`size`·`head`·`h`·`note`와 재고 하한(`"9,600+"`),
> 최상위 `groups`([[표시명, 영문]])도 넣을 수 있다 — 꾸민 제안서를 배포 없이 링크로 다시 낼 때(예: 2026-11-02 항공 구근 재발행).
> 행 = `[규격, 재고(구), 단가(원/구), 미리 채울 수량, 크레이트당 구수?]` — 다섯째 값이 있으면 그 규격은 **크레이트 단위**로 받는다
> (입력·전량·합계는 크레이트, 견적요청 수량은 구로 환산). 1크레이트 미만 남은 수량은 규격 이름에 '잔량'을 붙여 그 수량을 한 크레이트로 낸다.

고객에게 보내는 제안서를 **수량을 넣어 바로 견적을 요청할 수 있는 모바일 페이지**로 만든다.
2026-10-29 사용자 승인으로 도입.

## 흐름

```
고객: 카톡방 링크 열기 → 품목별 수량(구) 입력 → 합계 확인 → 연락처·동의 → [요청 보내기]
  → POST /api/quote (기존 견적 접수 API, 수정 없음)
  → 에어테이블 '견적요청' 레코드 생성 (요청번호 Q-YYYYMMDD-XXX)
  → 에어테이블 자동화 '카톡알림 · 웹 견적 신청' → Make '오픈가든 카톡 알림' → 대표 번호로 카톡
  → 접수 화면의 [요청 내용 복사]·[단톡방에 공유]로 고객이 기존 단톡방에도 붙여넣을 수 있다
```

- 품목요약에 단가·금액이 들어간다: `1. 알리움 퍼플 센세이션 @₩500 = ₩150,000 · 12/14 · 300개`
- 요청사항(memo)에 제안서 ID·고객명·합계·최소주문 미달 여부·고객 메모가 들어간다.
- 품목JSON의 sku는 `<제안서ID>:<품종키>|<규격>` 형식 — 어느 제안서에서 온 요청인지 구분된다.
- 카카오 정책상 단톡방 자동 전송은 불가 → 복사·공유 버튼으로 대신한다.

## 보안 (저장소가 공개라서)

- 품목·가격·고객정보는 빌드 때 **AES-256-GCM으로 암호화**해 HTML에 넣는다.
- 열쇠는 링크의 `#k=…` 부분에만 있다. `#` 뒤는 서버·로그로 전송되지 않으므로 링크를 받은 사람만 열람 가능.
  링크 끝이 잘리면 "제안서를 열 수 없습니다"가 뜬다.
- 제안서 JSON(가격·연락처·열쇠)은 `proposals/`에 두되 **커밋하지 않는다** (`.gitignore`).
  다시 빌드할 때 필요하므로 별도 보관(Claude 프로젝트 문서 등).
- 그 외: `/p/<무작위 ID>/`, `noindex` + `robots.txt`의 `Disallow: /p/`, 사이트 어디에서도 링크하지 않음.
  카탈로그 API(`api/catalog.js`)의 가격 화이트리스트는 그대로.

## 새 제안서 만들기

1. `proposals/<ID>.json` 작성. ID는 `용도-날짜-무작위8자` 예: `air-20261028-aff57e25`.
   - `items[].rows` = `[규격, 재고, 단가]` — 재고는 숫자(입력 상한 + [전량] 버튼) 또는 `"10,000+"` 같은 문자열(상한·전량 버튼 없음)
   - `minOrder` 0이면 최소주문 진행바를 숨긴다.
   - `mark`: `req`(★ 요청 품종) / `alt`(◇ 대체 제안, `alt`에 문구) / 빈칸
   - `customer`: `{ "name": "거래처명", "phone": "010-…" }` — 넣으면 "○○ 전용 제안" 표시 + 연락처 자동 입력
   - `key`: 비워두면 첫 빌드 때 생성되어 JSON에 저장된다 (다시 빌드해도 보낸 링크가 유지됨)
2. 사진을 `public/p/<ID>/img/<품종키>.jpg`로 넣는다 (정사각 크롭 권장, 600~900px).
3. 카톡 미리보기 이미지 `public/p/<ID>/og.jpg` (1200×630). 없으면 사이트 기본 `assets/og.jpg`.
4. `node tools/order-proposal/build.js tools/order-proposal/proposals/<ID>.json`
5. 커밋·배포 후 빌드가 출력한 `https://open-garden.co.kr/p/<ID>/#k=…` **전체**를 고객 카톡방에 보낸다.
   미리보기가 예전 것으로 뜨면 카카오 공유 디버거(developers.kakao.com/tool/debugger/sharing)에서 초기화.

마감된 제안서는 폴더째 지우면 링크가 404가 된다.

## 공동수입 주문서 (호게나르드 사진앨범, 2026-11-06)

- 주문 링크 한 줄의 품목JSON을 `{"v":1,"src":"hg-pool","minEach":200,"minTotal":600}`로 두면, 품목을 JSON이 아니라
  **호게나르드 DM 표에서 '공동주문' 체크 행**을 바로 읽어 그린다(`lib/hg-pool.js`, 인스턴스당 1분 재사용). 고객마다 줄만 하나씩 만들면 된다.
- 카드 = 식물 등록 마스터 1건. 같은 마스터의 P9·P12 행은 한 카드의 규격 줄. 국명·가격·재고는 DM, 특징·키·사진은 마스터 룩업.
  마스터 정보 검토상태가 '확인 필요'면 특징·키를 내보내지 않는다.
- 사진: `/api/order-photo?id=<마스터ID>` — 마스터 '사진' 첫 장에 로고 워터마크.
- 수량 규칙: `minEach` 품종(카드)당 최소, `minTotal` 전체 최소(단위 주). 못 채우면 요청 버튼이 잠긴다. 처음 [+]는 바로 minEach로 채운다.
- 품목 30개 넘으면 검색창이 뜬다. 묶음(탭)은 속 이름으로 자동(`lib/hg-pool.js` CATS).
- 품목 추가·가격 수정·마감 품목 빼기는 DM 표에서 하면 바로 반영된다(배포 불필요).
- (2026-11-07) 촘촘한 보기: 공동수입 주문서는 모바일 2열(태블릿 3열·PC 4열) 카드. 카드를 누르면 아래에서 상세 시트가 올라와 사진·특징·규격별 수량을 넣는다.
- 수종 안내 카드: 같은 수종(수국은 종까지)이 2품종 이상이면 그 묶음 맨 앞에 한 장. 문구는 에어테이블 `[영업] 수종 카드`(tblBieuBuvFfhC3Cu)에서 고친다. 품종 수·키·가격대는 자동. 카드를 누르면 품종 비교 목록.
- 사진: 카드 800px·상세 1600px, 주소에 첨부 ID(`v=`)가 붙어 사진을 바꾸면 캐시도 새로 잡힌다. 사진 주소는 한 번에 읽어 30분 재사용(에어테이블 초당 5회 제한 회피).
